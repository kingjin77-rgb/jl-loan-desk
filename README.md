# JL 대출데스크

법무법인 제이엘 상담사용 대출상담 프로그램.
단지·타입을 고르면 조건이 자동으로 채워지고, 고객 조건을 넣으면 **한도 · 물린 조건 ·
월 상환액 · 입주 시 부족자금**이 즉시 다시 계산됩니다.

> **⚠ 아직 규제 수치가 비어 있습니다.**
> **들어온 것**: 디딤돌·보금자리론·기금대출(승계)·버팀목의 금리표·한도·소득요건과
> 분양전환 구조값 — 사내 「분양전환 상담일지」에서 옮겼습니다(`meta.verified` 는 원문
> 대조 전까지 false). 프로파일을 **「실무」**로 바꾸면 이 상품 금리 비교가 바로 보입니다.
> **아직 없는 것**: LTV·DSR·스트레스금리·방공제. 이것들이 없으면 **최종 한도가 나오지 않습니다**
> (프로그램이 추정하지 않고 멈춥니다). [규제 수치 채우기](#규제-수치-채우기)를 보십시오.
> 기본 프로파일은 **「실무」**입니다. 「데모」는 프로그램 동작 확인용 가상 수치입니다.

## 여는 방법

**배포본**: `https://kingjin77-rgb.github.io/jl-loan-desk/`

### 휴대폰에 앱으로 설치하기

매번 주소를 여는 대신 홈 화면 아이콘으로 씁니다.

- **안드로이드(크롬)**: 위 주소를 열면 상단에 «설치» 줄이 뜹니다. 누르면 끝입니다.
  (안 보이면 브라우저 메뉴 → "홈 화면에 추가")
- **아이폰(사파리)**: 아래 **공유 버튼** → **"홈 화면에 추가"**

설치하면 주소창 없이 앱처럼 열리고, **비행기 모드에서도 계산이 됩니다**.
다만 오프라인일 때는 기기에 저장된 설정으로 계산하므로, 그 사이 규정이 바뀌었을
수 있다는 경고가 화면에 뜹니다. 통신이 되면 자동으로 최신 설정을 받습니다.

**내 컴퓨터에서**:
```bash
npx serve .
# 또는
python3 -m http.server 8000
```
그다음 브라우저에서 `http://localhost:8000` 을 엽니다.

> `index.html` 을 더블클릭해서 `file://` 로 여는 것은 **동작하지 않습니다.**
> 브라우저 보안 정책 때문에 설정 파일(JSON)을 읽지 못합니다. 반드시 위 방법으로 띄우십시오.

설치할 것은 없습니다. 빌드 과정도 없고, 서버도 없습니다. 모든 계산은 브라우저 안에서 끝납니다.

## 단지 없이도 계산됩니다

**단지 입력은 선택입니다.** 연소득과 금액만 넣으면 바로 계산됩니다.

| | 단지 없이 | 단지 넣으면 |
|---|---|---|
| 한도 (LTV·DSR·DTI·방공제) | ✅ | ✅ |
| 월 상환액 · 상환 스케줄 | ✅ | ✅ |
| 금리 시나리오 | ✅ | ✅ |
| 정책자금 비교 | ✅ | ✅ |
| 중도금 회차별 후불이자 | — | ✅ |
| **입주 시 부족자금** | — | ✅ |

기존 주택 매매·전세자금 상담은 단지 없이 쓰시면 됩니다.
분양 단지 상담일 때만 단지를 넣으면 「입주 때 현금이 얼마나 더 필요한지」가 나옵니다.

## 무엇을 계산하는가 — 정확도 등급과 함께

**모든 산출은 상담 가이드입니다.** 정확한 한도·금리·조건은 취급기관과 상담사 확인이 필요합니다.
다만 영역마다 정확도가 다르고, 화면이 그 차이를 표시합니다.

| 영역 | 등급 | 내용 |
|---|---|---|
| **기금대출 승계** (분양전환) | **정확** | 타입(51·59 → 5,500만 / 74·84 → 7,500만) · 연 2.8% · 20년 원리금균등 · 1년/3년 거치. 상담일지의 월 상환액 6개를 백원 단위까지 재현하는 테스트가 고정합니다. 거치는 고객 본인이 고르므로 화면은 「거치 가능」까지만 말합니다 |
| **분양전환** | **정확** (구조) | 필요자금(A−B+C−D) · 분할납부 한도 · 잔금유예 · LH 검증. **잔금유예 이자율만 미입력** |
| **디딤돌 · 보금자리론** | 정확 (확인 필요) | 금리표·한도·소득·자산 요건은 상담일지 기재값. 우대금리 항목별 폭·LTV 기준(공시가격?)은 확인 필요 |
| 버팀목 | 일부 | 소득 5천만원 요건만. 나머지 비어 있음 |
| **은행 일반 주담대** | **예시 · 가이드** | 규제값(LTV·DSR·스트레스·방공제·MCI)이 비어 있으면 **설명용 예시 수치**로 계산하고 결과마다 「예시」를 붙입니다. 실행일·현장·은행마다 다릅니다. 실제값을 넣으면 그 항목은 예시를 쓰지 않습니다 |

**타입을 고르면 기금승계가 기본 제안됩니다.** 대부분 기금을 쓰지만 모두가 쓰는 건 아니므로
「기금대출 승계 사용」을 끄면 디딤돌·보금자리·은행(예시)으로 넘어갑니다.
정책상품을 고른 계산에는 예시 규제값을 **쓰지 않습니다** — 상품 자체 조건으로 내고,
규제 상한이 빠졌다는 사실을 한도 패널 위에 밝힙니다.

그 밖에: 한도 합성(LTV·DSR·DTI·방공제·수기 상한의 최솟값과 **물린 조건**), 개선 레버(조건을
실제로 바꿔 재계산), 월 상환액·스케줄·금리 시나리오, 중도금 회차별 후불이자, 입주 시 부족자금.

### 반드시 알아야 할 네 가지

1. **금리가 두 개입니다.** 고객이 실제로 내는 *약정금리*는 월 상환액 계산에만,
   *스트레스 금리*는 DSR 한도 산정에만 씁니다. 프로그램이 이 둘을 섞지 않도록
   코드 수준에서 막아 두었습니다(`src/state/derive.js` 주석 참조).
2. **중도금대출은 DSR에서 빠지지만 잔금대출로 전환되는 순간 DSR이 적용됩니다.**
   중도금이 나왔다고 해서 잔금대출이 같은 금액으로 나오지 않습니다.
   화면에 항상 경고로 띄웁니다.
3. **우대금리에는 합계 상한이 있습니다.** 디딤돌은 우대 합계 0.5%p(다자녀 0.7%p)까지만
   깎입니다. 항목을 더 채워도 그 아래로는 안 내려갑니다. 화면이 「우대 상한 적용」으로
   표시하므로, 고객이 "더 채우면 더 내려가나요"라고 물을 때 그 자리에서 답할 수 있습니다.
   반면 **지방 소재 0.2%p 인하는 이 상한과 별개로** 더 내려갑니다.
4. **분양전환의 이자는 「잔금유예금」에 붙습니다** — 분할납부액이 아닙니다.
   분할납부액은 지금 정리하는 돈이고, 10년 뒤로 미루는 것은 남은 잔금입니다.
   (상담일지 84타입 예시로 검산됩니다: 분할납부 2억 → 미루는 잔금 7,500만원)

## 규제 수치 채우기

모든 규제 수치는 코드가 아니라 `data/policy/*.json` 에 있습니다. **코드를 고칠 필요가 없습니다.**

### 지금 상태

| 영역 | 상태 |
|---|---|
| `products/didimdol.*` `bogeumjari.*` `gigeum-seunggye.*` | 금리표·한도·소득·자산 요건 **입력됨** (출처: 사내 상담일지). 우대금리 **항목별 폭**은 비어 있습니다 |
| `products/beotimmok.*` | 부부합산소득 5천만원만 입력됨. 보증금 상한·한도·금리표는 비어 있음 |
| `policy/bunyangjeonhwan.*` | 구조값 입력됨. **잔금유예 적용금리만 비어 있습니다** — 상담일지에 이자율이 없습니다 |
| `policy/ltv.2026-09-28` | 규제지역 무주택 40%·생애최초 70%, 비규제 70%·생애최초 80%, 규제지역 총액 상한(15억↓6억/25억↓4억/초과 2억). **웹 검색 요약으로 옮김 — 원문 대조 필요.** 1주택·다주택은 비어 있음(예시로 메워짐) |
| `policy/dsr.2026-09-28` | 은행 40%·2금융 50%, 수도권 주담대 산정만기 360개월, 1주택 전세대출 이자만 반영. 신용·기타 산정만기는 비어 있음 |
| `policy/stress.2026-07-01` | 3단계 · 수도권·규제지역 **3.0%p×100%**, 지방 **1.5%p×50%**(2026 하반기). 혼합·주기형 비율 비어 있음 |
| `policy/bangongje.2026-01-02` | 시행령 제35947호: 서울 5,500만·과밀 4,800만·광역시등 2,800만·그밖 2,500만 (보증금 기준액 포함) |
| `policy/mci.*` | 비어 있음 (예시로 메워짐) |

**「원문 대조 필요」**: 이 값들은 웹 검색 요약에서 옮긴 것이고, 정부 원문(fsc.go.kr·myhome.go.kr·law.go.kr)은
개발 환경에서 접속이 막혀 직접 대조하지 못했습니다. 각 파일 `meta.출처URL`·`참고URL` 에 원문 주소가 있으니
열어 확인한 뒤 「규제 수치」 화면에서 「원문에서 직접 확인했습니다」를 체크하십시오.
화면 하단 **「출처 · 기준일」** 패널과 인쇄본에 어느 값이 어디서 왔는지가 항상 표시됩니다.

**생애최초 LTV 80%는 무조건이 아닙니다.** 디딤돌·보금자리론 모두 담보주택이
수도권(서울·인천·경기) 또는 규제지역이면 70%입니다. 상품 파일의 `limit.ltvOverrideWhen` 이 이 조건을 담고 있습니다.

### 채워야 할 파일

| 파일 | 확인할 곳 |
|---|---|
| `ltv.*.json` | 규제지역/주택수/목적별 LTV, 생애최초 우대, 금액 절대상한 |
| `dsr.*.json` | DSR·DTI 한도율, **DSR 산정만기 상한**, 기존부채 산정 규칙 |
| `stress.*.json` | 현재 시행 단계, 가산폭·하한·상한, 금리유형별·지역별 적용비율 |
| `bangongje.*.json` | 지역구분별 **최우선변제금** (보증금 기준액이 아닙니다 — 다른 수치입니다) |
| `mci.*.json` | MCI/MCG 가입 건수 제한, 한도, 취급 중단 여부 |
| `regions.*.json` | 투기과열지구·조정대상지역 목록 |

각 파일의 `_확인필요` 배열에 무엇을 찾아야 하는지 적어 두었습니다.

### 채우는 절차 — 화면에서 넣습니다

**JSON 파일을 손으로 고칠 필요가 없습니다.**

1. 화면 우상단 프로파일을 **「실무」**로 바꿉니다.
2. 노란 경고줄의 **「값 넣기」**(또는 메뉴 → **「규제 수치」**)를 누릅니다.
3. 탭(LTV / DSR·DTI / 스트레스 금리 / 방공제 / MCI·MCG / 분양전환)마다
   빈 칸을 채웁니다. 탭 이름 옆 괄호 숫자가 **남은 빈 칸 수**입니다.
   각 칸 옆에 원문에서 무엇을 확인해야 하는지 적혀 있습니다.
4. **원문에서 값을 확인하십시오. 기억이나 블로그 요약으로 채우지 마십시오** —
   "소액임차인 보증금 기준액"과 "최우선변제금액"이 섞여 돌아다니는 것,
   수도권 주담대 상한이 출처마다 다르게 적히는 것이 실제로 확인되었습니다.
5. 탭마다 **출처**를 적고 **「원문에서 직접 확인했습니다」**를 체크합니다.
   → 그 항목의 「미검증」 경고가 사라집니다.
   값을 넣은 것만으로는 검수완료로 보지 않습니다. 그건 확인이 아닙니다.
6. **저장**을 누릅니다.

넣은 값은 **이 브라우저에만** 저장되고 설정 파일은 그대로 남습니다
(배포본은 정적 파일이라 브라우저가 고칠 수 없습니다).
직접 입력한 값으로 계산 중일 때는 화면 위에 항상 그 사실이 표시됩니다.

**동료에게 넘기기**: 「내보내기」로 JSON 파일을 받아 전달하고, 상대는 「가져오기」로
읽어들입니다. 이 파일에는 규제 수치만 들어 있고 고객 정보는 들어 있지 않습니다.

**설정 파일에 영구히 넣으려면** `data/policy/*.json` 을 직접 고치고
`meta.verified` 를 `true` 로 바꾼 뒤 push 하십시오. 그러면 모든 상담사가 같은 값을 씁니다.

### 규제 수치가 없어도 되는 경우

정책자금 상품(디딤돌·보금자리론·기금승계)은 **자기 LTV·DTI 를 갖고 있습니다.**
비교표에서 **「이 상품으로 계산」**을 누르면 규제 수치가 비어 있어도 한도가 나옵니다.
이때는 한도 패널 맨 위에 **무엇이 빠졌는지**가 노란 띠로 표시되며,
규제 상한이 반영되지 않았으므로 실제 승인액보다 클 수 있습니다.

### 나중에 규제가 바뀌면

파일을 덮어쓰지 말고 **새 날짜의 파일을 추가**한 뒤 `data/manifest.json` 의 경로 한 줄만 바꿉니다.

```
data/policy/ltv.2026-09-19.json   ← 남겨 둡니다
data/policy/ltv.2027-01-05.json   ← 새로 만듭니다
```

구 파일을 남겨야 과거 상담기록을 **당시 규정 그대로** 재현할 수 있습니다.
상담기록에는 계산에 쓴 설정의 기준일이 함께 저장되고, 기준이 달라진 기록을 열면
프로그램이 그 사실을 알려 줍니다.

## 배포

GitHub Pages로 배포합니다. 빌드 과정이 없으므로 저장소를 그대로 서빙하면 됩니다.

설정 (한 번만):

1. 저장소 → **Settings → Pages**
2. **Source**: `Deploy from a branch`
3. **Branch**: `main` / `/ (root)` → **Save**

1~2분 뒤 `https://kingjin77-rgb.github.io/jl-loan-desk/` 에서 열립니다.
이후 `main` 에 push할 때마다 자동으로 갱신됩니다.

저장소 루트의 `.nojekyll` 이 Jekyll 처리를 끕니다(없으면 `_` 로 시작하는 파일이
무시되어 `data/complexes/_index.json` 을 못 읽습니다). 지우지 마십시오.

> **주의**: 배포된 사이트는 주소를 아는 사람이면 누구나 열 수 있습니다.
> 사이트에 담기는 것은 앱 코드·규제 설정·가상 샘플 단지뿐이고,
> 고객 정보는 상담사 브라우저에만 저장되어 외부로 나가지 않습니다.
> 사내에서만 열리게 하려면 배포 대신 공유폴더에 두고 각자 로컬로 띄우십시오.

## 테스트

```bash
node --test 'test/*.test.js'     # 설치할 의존성 없음
```

브라우저에서 같은 테스트를 돌릴 때는 `/test/` 주소를 엽니다. **새 테스트 파일을 만들면
`test/index.html` 의 import 목록에도 넣으십시오** — 빠지면 사무실 PC에서 "전부 통과"로
보이는데 실제로는 그 검사를 안 한 것입니다. 브라우저 쪽은 `test/runner.js` 의 assert 가
`node:assert` 모양을 흉내 내므로, node 에만 있는 메서드를 쓰면 브라우저에서만 깨집니다.

브라우저에서도 같은 테스트를 돌릴 수 있습니다: `/test/` 주소를 엽니다.
개발 도구가 없는 사무실 PC에서 "계산 엔진이 정상인지" 확인할 때 씁니다.

테스트는 `test/fixtures/` 의 고정 가상값으로 돌기 때문에 **실제 규제 수치를 갱신해도
깨지지 않습니다.** `data/` 에 대해서는 값이 아니라 구조만 검사합니다.

## 구조

```
index.html            상담 데스크 본화면
assets/css/           디자인 토큰 · 레이아웃 · 인쇄 스타일
src/core/             ★ 순수 계산 엔진 (DOM·네트워크 접근 없음, 규제 수치를 모름)
src/data/             설정 로딩 · 검증
src/state/            상태 + derive.js(계산의 유일한 진입점)
src/ui/               화면
src/io/               저장 · 내보내기 · 인쇄
sw.js                 서비스 워커 (홈 화면 설치 · 오프라인)
manifest.webmanifest  앱 정보 · 아이콘
data/policy/          ★ 규제 수치 (코드와 분리, 기준일·출처 필수)
data/products/        ★ 정책자금 상품 (금리표·한도·자격요건 — 코드는 요건을 모릅니다)
data/complexes/       단지 (샘플 + 템플릿만)
test/                 테스트 (node + 브라우저 공용)
```

도식은 7종입니다(한도 상한 비교 · DSR 여력 · 입주 시 자금수지 · 중도금 타임라인 ·
금리 시나리오 · 잔금유예 일정 · 상품별 한도). 색은 `assets/css/tokens.css` 의 `--viz-*`
에만 있고 코드에 hex 를 쓰지 않습니다. 색칠된 마크 위의 글자는 `--viz-on-bar`/`--viz-on-cat`
을 쓰며, 두 값이 나뉘어 있는 이유는 토큰 주석에 대비 수치와 함께 적어 두었습니다.

화면은 폭에 따라 둘로 갈립니다. **데스크톱은 2단 상담 데스크**(입력 레일 + 결과),
**모바일은 [입력]/[결과] 두 탭**입니다. 모바일에서 세로로 쌓으면 화면 7배 길이가
되기 때문입니다. `assets/css/mobile.css` 한 파일에 모여 있습니다.

> **새 소스 모듈을 추가하면 `sw.js` 의 `SHELL` 목록에도 넣어야 합니다.**
> 빠지면 오프라인에서 앱이 뜨지 않습니다. 테스트가 이를 검사합니다.

설계 원칙은 각 파일 상단 주석에 적어 두었습니다. 특히 다음 세 곳을 먼저 읽으십시오:
`src/core/limit.js`(한도 합성), `src/core/amortize.js`(상환 계산),
`src/state/derive.js`(두 금리를 섞지 않는 방법).

## 아직 안 된 것

- **디딤돌 우대금리의 항목별 폭** — 상담일지에는 합계 상한(0.5%p / 다자녀 0.7%p)만 있어
  개별 항목은 비워 두었습니다. 화면에 「우대폭 미설정 ○건」으로 표시됩니다.
- **잔금유예 적용금리** — 상담일지에 이자율이 적혀 있지 않습니다. 화면에서 직접 넣을 수 있게
  해 두었지만, 확인해서 `policy/bunyangjeonhwan.*.json` 에 넣는 편이 낫습니다.
- **생애최초 LTV 80%** 의 적용 조건 — 상담일지의 「생초 80% 수도권 제외」가
  '수도권은 70%'인지 확인이 필요합니다. 현재는 70%로 두었습니다.
- **디딤돌 LTV 의 기준** — 상담일지는 '공시가격의 70%'로 적고 있습니다. 감정가·시세 기준과
  결과가 크게 달라지므로 확인이 필요합니다. 화면의 한도 산식에 기준을 함께 표시합니다.
- 전용 60~74㎡ 구간의 기금대출 승계 한도와 최소 잔금유예금 (상담일지에 없는 구간).
- 체증식 상환 — 취급 기관마다 정의(증가율·증가 주기)가 달라 기준을 받아야 구현할 수 있습니다.
- 저장된 상담 목록의 검색·비교 화면.
