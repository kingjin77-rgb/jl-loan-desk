# JL 대출데스크

법무법인 제이엘 상담사용 대출상담 프로그램.
단지·타입을 고르면 조건이 자동으로 채워지고, 고객 조건을 넣으면 **한도 · 물린 조건 ·
월 상환액 · 입주 시 부족자금**이 즉시 다시 계산됩니다.

> **⚠ 지금 상태로 실제 상담에 쓰지 마십시오.**
> LTV·DSR·스트레스금리·방공제 등 규제 수치가 아직 채워져 있지 않습니다.
> 기본으로 켜져 있는 「데모」 프로파일은 **가상의 숫자**입니다.
> [규제 수치 채우기](#규제-수치-채우기)를 먼저 끝내야 합니다.

## 여는 방법

**배포본**: `https://kingjin77-rgb.github.io/jl-loan-desk/`

### 휴대폰에 앱으로 설치하기

매번 주소를 여는 대신 홈 화면 아이콘으로 씁니다.

- **안드로이드(크롬)**: 위 주소를 열면 상단에 «설치» 줄이 뜹니다. 누르면 끝입니다.
  (안 보이면 브라우저 메뉴 → "홈 화면에 추가")
- **아이폰(사파리)**: 아래 **공유 버튼** → **"홈 화면에 추가"**

설치하면 주소창 없이 앱처럼 열리고, **비행기 모드에서도 계산이 됩니다**.
다만 오프라인일 때는 기기에 저장된 설정으로 계산하므로, 그 사이 규정이 바뀌었을
수 있다는 경고가 화면에 뜹니다. 통신이 되면 자동으로 최신 설정을 받습니다.

**내 컴퓨터에서**:
```bash
npx serve .
# 또는
python3 -m http.server 8000
```
그다음 브라우저에서 `http://localhost:8000` 을 엽니다.

> `index.html` 을 더블클릭해서 `file://` 로 여는 것은 **동작하지 않습니다.**
> 브라우저 보안 정책 때문에 설정 파일(JSON)을 읽지 못합니다. 반드시 위 방법으로 띄우십시오.

설치할 것은 없습니다. 빌드 과정도 없고, 서버도 없습니다. 모든 계산은 브라우저 안에서 끝납니다.

## 단지 없이도 계산됩니다

**단지 입력은 선택입니다.** 연소득과 금액만 넣으면 바로 계산됩니다.

| | 단지 없이 | 단지 넣으면 |
|---|---|---|
| 한도 (LTV·DSR·DTI·방공제) | ✅ | ✅ |
| 월 상환액 · 상환 스케줄 | ✅ | ✅ |
| 금리 시나리오 | ✅ | ✅ |
| 정책자금 비교 | ✅ | ✅ |
| 중도금 회차별 후불이자 | — | ✅ |
| **입주 시 부족자금** | — | ✅ |

기존 주택 매매·전세자금 상담은 단지 없이 쓰시면 됩니다.
분양 단지 상담일 때만 단지를 넣으면 「입주 때 현금이 얼마나 더 필요한지」가 나옵니다.

## 무엇을 계산하는가

| 영역 | 내용 |
|---|---|
| 한도 | LTV · DSR · DTI · 방공제 차감 · 수기 상한을 각각 산출한 뒤 **최솟값**을 취하고, **어느 조건이 한도를 막고 있는지**와 2순위와의 격차를 함께 보여줍니다 |
| 개선 레버 | "기존 대출을 갚으면 +○○원" 같은 안내. 하드코딩이 아니라 조건을 실제로 바꿔 **다시 계산한 결과**입니다 |
| 월 상환액 | 원리금균등 / 원금균등, 거치기간, 전체 상환 스케줄, 금리 +0.5/+1.0/+1.5%p 시나리오 비교 |
| 중도금 | 회차별 실행액과 **이자후불제 누적이자**(회차마다 경과일수가 다르므로 따로 계산) |
| 잔금 | 입주 시 소요자금 − 조달 = **부족자금**. 이 한 줄이 상담의 결론입니다 |

### 반드시 알아야 할 두 가지

1. **금리가 두 개입니다.** 고객이 실제로 내는 *약정금리*는 월 상환액 계산에만,
   *스트레스 금리*는 DSR 한도 산정에만 씁니다. 프로그램이 이 둘을 섞지 않도록
   코드 수준에서 막아 두었습니다(`src/state/derive.js` 주석 참조).
2. **중도금대출은 DSR에서 빠지지만 잔금대출로 전환되는 순간 DSR이 적용됩니다.**
   중도금이 나왔다고 해서 잔금대출이 같은 금액으로 나오지 않습니다.
   화면에 항상 경고로 띄웁니다.

## 규제 수치 채우기

모든 규제 수치는 코드가 아니라 `data/policy/*.json` 에 있습니다. **코드를 고칠 필요가 없습니다.**

### 채워야 할 파일

| 파일 | 확인할 곳 |
|---|---|
| `ltv.*.json` | 규제지역/주택수/목적별 LTV, 생애최초 우대, 금액 절대상한 |
| `dsr.*.json` | DSR·DTI 한도율, **DSR 산정만기 상한**, 기존부채 산정 규칙 |
| `stress.*.json` | 현재 시행 단계, 가산폭·하한·상한, 금리유형별·지역별 적용비율 |
| `bangongje.*.json` | 지역구분별 **최우선변제금** (보증금 기준액이 아닙니다 — 다른 수치입니다) |
| `mci.*.json` | MCI/MCG 가입 건수 제한, 한도, 취급 중단 여부 |
| `regions.*.json` | 투기과열지구·조정대상지역 목록 |

각 파일의 `_확인필요` 배열에 무엇을 찾아야 하는지 적어 두었습니다.

### 채우는 절차

1. 원문에서 값을 확인합니다. **기억이나 블로그 요약으로 채우지 마십시오** —
   조사 과정에서 "소액임차인 보증금 기준액"과 "최우선변제금액"이 섞여 돌아다니는 것,
   수도권 주담대 상한이 출처마다 다르게 적히는 것이 실제로 확인되었습니다.
2. `meta.출처` 와 `meta.출처URL` 에 확인한 문서를 적습니다.
3. 값을 다 채웠으면 `meta.verified` 를 `true` 로 바꿉니다.
   → 화면의 붉은 경고 배너가 사라집니다.
4. 화면 우상단에서 프로파일을 **「실무」**로 바꿉니다.

### 나중에 규제가 바뀌면

파일을 덮어쓰지 말고 **새 날짜의 파일을 추가**한 뒤 `data/manifest.json` 의 경로 한 줄만 바꿉니다.

```
data/policy/ltv.2026-09-19.json   ← 남겨 둡니다
data/policy/ltv.2027-01-05.json   ← 새로 만듭니다
```

구 파일을 남겨야 과거 상담기록을 **당시 규정 그대로** 재현할 수 있습니다.
상담기록에는 계산에 쓴 설정의 기준일이 함께 저장되고, 기준이 달라진 기록을 열면
프로그램이 그 사실을 알려 줍니다.

## 단지 데이터

**이 저장소는 공개(public)입니다. 실제 단지 데이터를 커밋하지 마십시오.**
저장소와 배포된 사이트 양쪽에서 그대로 내려받을 수 있게 되어,
분양가·회차 일정·취급은행이 인터넷에 공개됩니다.

대신 화면의 **「파일 열기」**로 내 컴퓨터의 단지 JSON 을 불러와 씁니다.
저장소에는 가상의 샘플 단지 하나와 템플릿만 둡니다.

JSON을 직접 손으로 쓰고 싶다면 [DATA-GUIDE.md](DATA-GUIDE.md) 를 보십시오
(앱에서 만드는 편이 훨씬 빠릅니다).

## 상담기록

- **저장**: 이 PC의 이 브라우저에만 저장됩니다. 서버로 전송되지 않습니다.
- **내보내기**: JSON 파일로 저장해 다른 PC로 옮기거나 보관할 수 있습니다.
- **인쇄**: A4 상담기록서로 출력됩니다(상환 스케줄은 연 단위로 요약).

  「불러오기 → 이 PC의 상담기록 전체 삭제」로 정리하십시오.

## 배포

GitHub Pages로 배포합니다. 빌드 과정이 없으므로 저장소를 그대로 서빙하면 됩니다.

설정 (한 번만):

1. 저장소 → **Settings → Pages**
2. **Source**: `Deploy from a branch`
3. **Branch**: `main` / `/ (root)` → **Save**

1~2분 뒤 `https://kingjin77-rgb.github.io/jl-loan-desk/` 에서 열립니다.
이후 `main` 에 push할 때마다 자동으로 갱신됩니다.

저장소 루트의 `.nojekyll` 이 Jekyll 처리를 끕니다(없으면 `_` 로 시작하는 파일이
무시되어 `data/complexes/_index.json` 을 못 읽습니다). 지우지 마십시오.

> **주의**: 배포된 사이트는 주소를 아는 사람이면 누구나 열 수 있습니다.
> 사이트에 담기는 것은 앱 코드·규제 설정·가상 샘플 단지뿐이고,
> 고객 정보는 상담사 브라우저에만 저장되어 외부로 나가지 않습니다.
> 사내에서만 열리게 하려면 배포 대신 공유폴더에 두고 각자 로컬로 띄우십시오.

## 테스트

```bash
node --test 'test/*.test.js'     # 설치할 의존성 없음
```

브라우저에서도 같은 테스트를 돌릴 수 있습니다: `/test/` 주소를 엽니다.
개발 도구가 없는 사무실 PC에서 "계산 엔진이 정상인지" 확인할 때 씁니다.

테스트는 `test/fixtures/` 의 고정 가상값으로 돌기 때문에 **실제 규제 수치를 갱신해도
깨지지 않습니다.** `data/` 에 대해서는 값이 아니라 구조만 검사합니다.

## 구조

```
index.html            상담 데스크 본화면
assets/css/           디자인 토큰 · 레이아웃 · 인쇄 스타일
src/core/             ★ 순수 계산 엔진 (DOM·네트워크 접근 없음, 규제 수치를 모름)
src/data/             설정 로딩 · 검증
src/state/            상태 + derive.js(계산의 유일한 진입점)
src/ui/               화면
src/io/               저장 · 내보내기 · 인쇄
sw.js                 서비스 워커 (홈 화면 설치 · 오프라인)
manifest.webmanifest  앱 정보 · 아이콘
data/policy/          ★ 규제 수치 (코드와 분리, 기준일·출처 필수)
data/complexes/       단지 (샘플 + 템플릿만)
test/                 테스트 (node + 브라우저 공용)
```

화면은 폭에 따라 둘로 갈립니다. **데스크톱은 2단 상담 데스크**(입력 레일 + 결과),
**모바일은 [입력]/[결과] 두 탭**입니다. 모바일에서 세로로 쌓으면 화면 7배 길이가
되기 때문입니다. `assets/css/mobile.css` 한 파일에 모여 있습니다.

> **새 소스 모듈을 추가하면 `sw.js` 의 `SHELL` 목록에도 넣어야 합니다.**
> 빠지면 오프라인에서 앱이 뜨지 않습니다. 테스트가 이를 검사합니다.

설계 원칙은 각 파일 상단 주석에 적어 두었습니다. 특히 다음 세 곳을 먼저 읽으십시오:
`src/core/limit.js`(한도 합성), `src/core/amortize.js`(상환 계산),
`src/state/derive.js`(두 금리를 섞지 않는 방법).
